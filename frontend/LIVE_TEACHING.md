# Live teaching

Open the lesson tutor's Learning tools menu and select Live tutor. Voice teaching starts automatically, subject to the browser's microphone permission. The sidebar closes. The lesson remains visible through the transparent overlay, compact audio controls appear at the bottom, and the floating tutor button becomes a voice orb. The waveform scrolls using actual microphone or tutor audio samples and settles during silence. The orb opens a small chat bubble. If voice fails or microphone access is unavailable, typing can start a silent ElevenLabs text conversation. Pause mutes microphone and audio while preserving the connection; Resume continues the conversation. The close control ends the teaching session.

## Configuration

Closing Live Tutor suspends an unfinished teaching session and waits for its checkpoint save. Reopening the same lesson restores the saved concept, transcript and section rather than repeating the initial interview. Only a genuinely completed teaching plan is marked completed. Sessions incorrectly marked completed by earlier versions are not reopened automatically.

## Admin controls and daily limits

Admin → AI settings now includes an independent ElevenLabs panel (it remains available if OpenRouter is unavailable). It reads the account's remaining character-credit allowance, cycle usage, reset date and available voices. Missing provider permissions show a warning, not a fabricated balance. It never returns the API key. Only the exact `ADMIN` role can access provider balances or modify global settings.

Administrators can enable/disable new Live Tutor connections, select or enter a provider-accessible voice, set maximum duration (1–30 minutes), and configure the shared daily/weekly Pro AI allowance through the existing plan entitlements. Chat, guided dialogue and Live Tutor all use this allowance. Eligible institutional learners retain their effective plan limits. There is no separate five-session live cap. The old database/API `dailySessionLimit` field is retained for backward compatibility only, is not enforced, and is no longer shown as an active admin setting.

Each successful chat reply, guided dialogue response, or provider-verified live session costs one shared AI use. Live connections include text mode, reopening and reconnecting. Pause/resume on the same connection does not count again. A signed URL alone is not a paid use. Known exhausted provider balances are rejected before reservation; failed connections, provider error events, empty responses and truncated streams do not count. Checkpoints, lesson actions and live conversation turns do not consume additional uses. Daily usage resets at midnight UTC+8; weekly usage resets on Monday. Existing valid `tutor-live` usage rows are included in both windows and in the combined breakdown without rewriting history.

All three modes serialize their quota check and ledger changes under the same PostgreSQL transaction-scoped learner lock. Streams and live connections reserve a slot (`hold-chat`/`hold-live`) without appearing as used. Holds prevent parallel requests from overbooking the allowance and expire from enforcement after 45 minutes. A stream is charged only on a completed, non-empty `done` response; error/timeout/disconnection leaves an excluded `failed-*` audit record. Live reservations are bound server-side to the exact conversation ID in the single-use signed URL; browser callbacks can only request reconciliation, not declare success or issue refunds. The server verifies agent/conversation identity and provider transcript/status. A provider `failed` status reverses even a previously observed partial live success. Minute reconciliation covers tab closure and provider-report delays. Metadata-unavailable holds are not charged on guesswork. Migration V78 adds provider identity/verification columns. Either shared window can block a new use; quota failures retain the standard usage-limit response rather than appearing as provider failures. Admin preview is not charged to a learner. Existing connections retain their previous voice/duration; disabling Live Tutor blocks new sessions, not active ones.

Settings persist in `live_tutor_settings` (migration V77); usage reuses `ai_generation_usage`. Apply migration V78 for provider-verified delivery tracking in production. Provider credits are independent of each learner's shared plan allowance.

Tests: `node scripts/tests/live-admin-settings.browser.mjs` exercises the real admin form against mocked APIs, including voice/cap saves, missing-balance warnings and the daily-only learner meter. Backend `LiveTutorQuotaServiceTest`, `ElevenLabsSettingsServiceTest`, and `AiSettingsControllerTest` cover cap enforcement, failure accounting, lock ordering, settings validation and access control. No speech generation is required for these checks.

## Backend contracts

`POST /api/ai/tutor/live/session` accepts `{lessonId}`. It authenticates the caller, enforces AI tutor and lesson entitlements, retrieves the lesson from PostgreSQL, restores an unfinished session, and returns server lesson content, a short-lived ElevenLabs signed URL, checkpoint, and recent transcript. The API does not accept frontend lesson text as its source of curriculum.

`POST /api/ai/tutor/live/sessions/{sessionId}/events` accepts a supported event type, teaching state, bounded context object, and bounded transcript. Ownership is checked server-side. These are conversation records, never assessment scores or claims of course completion. No audio recordings are stored by this implementation.

## Implemented and limits

### LangGraph / LangChain typing coordination

Live Tutor now calls the Python `live_turns` LangGraph through authenticated Java `POST /api/ai/tutor/live/sessions/{id}/turn`. Java derives owner identity from the JWT and checks teaching-session ownership; Python uses the existing service-key-protected tutor router. Each connection has ordered, monotonic events and a separate durable graph thread. PostgreSQL checkpointing and a cross-worker advisory lock prevent concurrent graph writes from racing. Stale event sequence numbers cannot release a newer typing hold.

The actual graph nodes are `apply_activity → prepare_answer_evaluation → wait_or_continue` (evaluation is conditional on a submitted answer). States include composing, paused, closed, evaluating an answer and teaching. Both continuation requests and new lesson tool actions check graph permission. LangChain `HumanMessage`/`AIMessage` history and `ChatPromptTemplate` prepare bounded evaluation context after **Send**; ElevenLabs still performs the conversational response and speech. This does not replace the voice agent with a second LangChain LLM, and no model call runs for a typing event. Unsent drafts are never included in graph events. A failed submission keeps the input draft intact rather than sending it to ElevenLabs or advancing the lesson.

Tests: Python `python -m pytest --confcutdir=tests/live_turns tests/live_turns -q` uses a real compiled graph with an in-memory saver. `python -m scripts.check_live_turns` verifies actual PostgreSQL checkpointing on an isolated smoke-test thread and deletes only that thread afterward. Frontend `live-turn-coordinator.test.mjs` covers event ordering/privacy/retry, while `live-typing.browser.mjs` verifies the graph handoff and retained draft on HTTP 503 using mocked API/provider responses. Java `LiveTutorControllerTest` checks JWT authentication, session ownership, event validation and that graph activity does not consume another daily session.

Live Tutor chat signals active drafting to the provider using `sendUserActivity()` every second and a replaceable `learner_typing` context flag. Only the flag is shared, never the unsent text. The local teaching controller suspends continuation, answer-window hints and new lesson actions while the open chat contains a draft (including IME composition). A visible “You’re typing · tutor is waiting for Send” status confirms the hold. Sending releases the hold and evaluates the submitted answer before continuing. Clearing the draft or closing chat releases it; ordinary timers restart rather than treating drafting time as unanswered silence. Explicit Pause still takes precedence. [Provider activity API](https://elevenlabs.io/docs/eleven-agents/libraries/java-script).

- Basic teacher prompt: short explanations, why/how, concrete examples, adaptive correction, and understanding checks using supplied curriculum.
- Provider voice interruptions and same-connection pause/resume; saved transcript and UI context are supplied on reconnect. Exact concept mastery is not inferred from scrolling.
- Debounced section tracking, text selection, image metadata, tabs, and annotated lesson-tool clicks. Updates are contextual and do not ask the teacher to speak on every click.
- Full-screen audio controls and floating text chat without a microphone/headset.
- An explicit teaching controller separates diagnostic questions, explanations, demonstrations, recitation, feedback, answer windows, transitions, pause, completion, and error recovery. Ordinary explanations advance after playback; real questions wait 20 seconds, allow one hint, then move to a model answer after another 15 seconds. Silence is never recorded as mastery or agreement.
- Registered ElevenLabs client tools `teaching_step`, `lesson_catalog`, and `lesson_action` plan the next segment and operate only catalogued elements inside the current lesson. Section scrolling, tabs, idempotent accordion expansion/collapse, flip-card front/back selection, tool focus and image focus return verified UI state. Manual wheel/touch exploration temporarily suppresses tutor navigation.
- Checkpoints include the teaching phase, current/finished concepts, unfinished spoken segment, question context, and bounded transition trace. Interrupted-response corrections update the transcript. Reconnect restores that context; it is not a certified mastery record.
- The provider's previous seven-second silence turn is changed to 30 seconds with patient turn-taking; the teaching controller schedules teaching much sooner and manages genuine answer windows. Generic check-ins, permission-to-continue questions and bracketed delivery tags are prohibited in the configured teacher prompt; known tags are stripped from readable transcripts.

Still required for the full hybrid specification: actual image input with authorized retrieval, richer adapters for controls beyond the registered lesson widgets, server-evaluated oral exams integrated with existing assessment records, and end-to-end microphone tests for interruption latency and reconnection. Image metadata alone is explicitly labelled as insufficient to see image pixels. Oral recitation currently uses conversational feedback, not official grades or saved assessment results.

## Checks

Lesson interaction adapters now perform real clicks, not just focus: tool containers reveal their first registered control, tabs select, accordions expand, cards flip, image hotspots open, and image/video viewers expand (no automatic video playback). Each `teaching_step` uses its section ID and concept/control-label overlap to reveal the matching widget before the provider receives the tool result. This is conservative label matching, not semantic visual understanding: for ambiguous or nested content the tutor must use exact catalog IDs via `lesson_action`, then refresh the catalog. Only tutor-opened media viewers are closed when switching focus or exiting. Typing/pause and manual-exploration protections still apply; question steps do not automatically reveal card answers. No backend contract or ElevenLabs account configuration changes are required for these adapters.
